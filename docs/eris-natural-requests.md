# Eris : outils natifs et réponses libres

Depuis le nettoyage du 19 novembre 2026, tous les modèles suivent le même parcours de fonctions natives. Les menus de candidats, boutons Eris, confirmations systématiques, interpréteurs de numéros et routeurs d'intention par expressions régulières ont été supprimés. Les anciens boutons ne fonctionnent plus.

Le modèle choisit les outils et interprète leurs résultats. « Demande Madagascar » passe par `lookup_media`, puis `request_media` avec l'identifiant catalogue vérifié. « Tous les films Madagascar » utilise aussi `movie_collection` pour demander les vrais volets. Les résultats proches restent des données pour le modèle ; ils ne deviennent pas automatiquement une liste à choisir. Une ambiguïté réelle ou une saison impossible à déduire appelle une question libre.

Une demande explicite autorise l'ajout. Une opinion, une question d'existence ou une recommandation ne l'autorise pas. Cette interprétation appartient au modèle ; le code n'essaie plus de reconnaître une grammaire de consentement. Le code conserve les schémas typés, l'identité Discord de l'auteur, les accès personnels, les quotas, les vérifications de révocation et les reçus persistants contre les doublons. Les secrets ne sont jamais des arguments choisis par le modèle.

`request_media` exige un bénéficiaire explicite : `targetDiscordId: "self"` pour l'auteur, ou l'ID vérifié d'un membre mentionné ou présent dans le contexte. Un administrateur configuré peut demander pour un autre compte associé et lire ses demandes avec `status` et le même bénéficiaire. L'API revérifie les droits de l'auteur, l'association du bénéficiaire et l'identité Seerr ; elle emploie le véritable propriétaire pour l'écriture et son reçu. Un compte manquant ou un accès refusé ne se transforme jamais en demande pour l'administrateur. Les résultats indiquent `requestOwner`, `actedBy` et si l'attribution est vérifiée. Une ancienne demande réattribuée dans Seerr ne permet plus à un reçu local d'annoncer un mauvais propriétaire. Le corps signé des interactions est transporté en base64 pour conserver exactement ses espaces et mentions.

`ordre66` et `ordre 66` sont des interpellations dans un message public, sans commande slash. Eris identifie l'interlocuteur à partir d'une mention, d'une réponse Discord vérifiée ou de six messages publics récents. Elle écrit une courte réplique de comédie horrifique dans sa propre voix ; l'auteur de l'ordre ne peut pas être la cible. Le code refuse une cible inconnue ou l'auteur lui-même et affiche la mention vérifiée d'un membre choisi, afin qu'un « tu » ne paraisse pas viser l'auteur. Un test ou une démonstration sans membre désigné peut utiliser un adversaire imaginaire anonyme, sans identifiant Discord ni membre du salon pris pour victime. L'absence de destinataire réel n'impose donc pas une clarification : le modèle interprète l'intention avec l'échange. S'il s'agit d'attaquer un interlocuteur réel non identifiable, il demande qui viser. Ce parcours sans destinataire ne sélectionne aucun ID et utilise le JSON de discussion normal ; une réponse d'attaque avec une cible refusée n'est jamais publiée. Les démonstrations et clarifications restent libres, sans message préécrit. La discussion ordinaire sait aussi accepter une relance demandant un test sans cible. Les vrais échecs de génération et de format restent des erreurs techniques. Aucun outil média, mémoire privée ni pouvoir d'action externe n'est accessible par le parcours dédié. Une critique du style ne supprime pas le registre violent fictif et ne permet pas au personnage d'annoncer une reprogrammation. Voir la [recette de voix](../evals/eris/order66-voice-review.md).

Les dix-neuf outils renvoient des faits structurés : catalogue, ajouts, Plex, recommandations, nouveautés, demandes, mesures NAS, web, cinéma, diagnostic, anime/manga, cadeaux, suivis, réglages et créations Discord. Le modèle reçoit ces faits et rédige lui-même succès, erreur ou clarification. Aucun préambule ni phrase de secours du personnage n'est ajouté par le code. L'oubli et le réglage de participation utilisent aussi une formulation du modèle après exécution vérifiée. L'aide et les formulaires des commandes Discord restent des éléments d'interface.

Les appels Chat Completions utilisent `tool_calls` et les réponses `tool`. Responses utilise `function_call` et `function_call_output`, en conservant le raisonnement chiffré nécessaire à la continuation. Aucun outil hébergé par le fournisseur n'est exécuté. La boucle est bornée à huit générations et six appels par génération. Les relances attendent le tour actif, sans ancien délai de dix secondes. Un moteur doit prendre en charge les fonctions natives ; aucun repli vers les anciens plans textuels n'existe.

Le 19 novembre au soir, la production a été reconnectée au compte ChatGPT propre à Eris et repassée sur Responses avec `gpt-6-luna`. Le service `eris-auth` renouvelle cet accès ; le montage Zro a été retiré du bot, sans repli vers Zro ni clé API payante. Un seul contrôle OpenAI de connexion et de fonction native a consommé 89 jetons. Le retour HTTP 402 de Zro ne permet pas de conclure à un solde épuisé ni de chiffrer sa consommation. La demande Seerr #415 a été réattribuée de Hugo à Keftcha après sauvegarde, en conservant son statut et son média, sans création ni notification supplémentaire.

Une demande créée ne prouve ni disponibilité Plex, ni arrivée future, ni notification programmée. Un résultat d'écriture inconnu ne déclenche pas un nouvel envoi automatique. Les résultats personnels d'outils ne deviennent pas des souvenirs durables de discussion. Les filtres de visionnage, les cadeaux et les réglages restent privés. Les serveurs de discussion seule ne reçoivent aucune fonction externe.

Si le modèle est indisponible ou invalide sa réponse, le transport affiche uniquement un code technique `ERIS_UNAVAILABLE` ou `ERIS_BUSY`. Il n'invente pas une réplique d'Eris. L'effacement local demandé fonctionne même si le modèle ne peut pas en rédiger la confirmation.

La recette couvre les dix-neuf fonctions, leurs erreurs, les deux transports, le rejeu, les révocations, les limites privées et les résultats incertains. Le laboratoire facultatif `TestLiveAgentMadagascar` utilise le modèle configuré, des écritures média simulées et de vraies lectures web ; `TestLiveAgentStructuredTools` vérifie aussi mesures, réglages, diagnostic et cadeaux. Ces essais n'envoient aucun message Discord ni ajout Seerr réel. La qualité de chaque réponse libre reste une propriété du modèle, pas une garantie du validateur.
