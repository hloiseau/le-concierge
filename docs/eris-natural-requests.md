# Eris : outils natifs et réponses libres

Depuis le nettoyage du 19 novembre 2026, tous les modèles suivent le même parcours de fonctions natives. Les menus de candidats, boutons Eris, confirmations systématiques, interpréteurs de numéros et routeurs d'intention par expressions régulières ont été supprimés. Les anciens boutons ne fonctionnent plus.

Le modèle choisit les outils et interprète leurs résultats. « Demande Madagascar » passe par `lookup_media`, puis `request_media` avec l'identifiant catalogue vérifié. « Tous les films Madagascar » utilise aussi `movie_collection` pour demander les vrais volets. Les résultats proches restent des données pour le modèle ; ils ne deviennent pas automatiquement une liste à choisir. Une ambiguïté réelle ou une saison impossible à déduire appelle une question libre.

Une demande explicite autorise l'ajout. Une opinion, une question d'existence ou une recommandation ne l'autorise pas. Cette interprétation appartient au modèle ; le code n'essaie plus de reconnaître une grammaire de consentement. Le code conserve les schémas typés, l'identité Discord, les accès personnels, les quotas, les vérifications de révocation et les reçus persistants contre les doublons. L'identité et les secrets ne sont jamais des arguments choisis par le modèle.

Les dix-neuf outils renvoient des faits structurés : catalogue, ajouts, Plex, recommandations, nouveautés, demandes, mesures NAS, web, cinéma, diagnostic, anime/manga, cadeaux, suivis, réglages et créations Discord. Le modèle reçoit ces faits et rédige lui-même succès, erreur ou clarification. Aucun préambule ni phrase de secours du personnage n'est ajouté par le code. L'oubli et le réglage de participation utilisent aussi une formulation du modèle après exécution vérifiée. L'aide et les formulaires des commandes Discord restent des éléments d'interface.

Les appels Chat Completions utilisent `tool_calls` et les réponses `tool`. Responses utilise `function_call` et `function_call_output`, en conservant le raisonnement chiffré nécessaire à la continuation. Aucun outil hébergé par le fournisseur n'est exécuté. La boucle est bornée à huit générations et six appels par génération. Les relances attendent le tour actif, sans ancien délai de dix secondes. Un moteur doit prendre en charge les fonctions natives ; aucun repli vers les anciens plans textuels n'existe.

Une demande créée ne prouve ni disponibilité Plex, ni arrivée future, ni notification programmée. Un résultat d'écriture inconnu ne déclenche pas un nouvel envoi automatique. Les résultats personnels d'outils ne deviennent pas des souvenirs durables de discussion. Les filtres de visionnage, les cadeaux et les réglages restent privés. Les serveurs de discussion seule ne reçoivent aucune fonction externe.

Si le modèle est indisponible ou invalide sa réponse, le transport affiche uniquement un code technique `ERIS_UNAVAILABLE` ou `ERIS_BUSY`. Il n'invente pas une réplique d'Eris. L'effacement local demandé fonctionne même si le modèle ne peut pas en rédiger la confirmation.

La recette couvre les dix-neuf fonctions, leurs erreurs, les deux transports, le rejeu, les révocations, les limites privées et les résultats incertains. Le laboratoire facultatif `TestLiveAgentMadagascar` utilise le modèle configuré, des écritures média simulées et de vraies lectures web ; `TestLiveAgentStructuredTools` vérifie aussi mesures, réglages, diagnostic et cadeaux. Ces essais n'envoient aucun message Discord ni ajout Seerr réel. La qualité de chaque réponse libre reste une propriété du modèle, pas une garantie du validateur.
