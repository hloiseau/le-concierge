# Ouicheur personnel dans Eris

Chantier #88 de #78 : consulter ses listes et comparer les envies, uniquement dans `/eris` privé. Le plan `gifts` accepte le nom de liste (`query`) et une recherche facultative dans les envies (`text`). Une liste ambiguë demande une précision ; huit listes ou cinq envies maximum sont présentées. La recherche ne réserve ni n’achète rien.

Configuration : `OUICHEUR_URL` est l’origine HTTPS publique de l’instance installée, sans chemin, identifiant, query ou fragment. `OUICHEUR_REVISION` doit être `bbd143bc03201205a35b0a1009bf8476e110f16a` (version 1.4.5 auditée). Aucun secret d’opérateur n’est ajouté. Le Hub affiche une connexion dans Mon compte quand cette intégration est configurée. Le membre y saisit ses identifiants personnels ; le champ identifiant peut rester vide pour son propre compte propriétaire. Le mot de passe n’est ni enregistré ni transmis au modèle. Le cookie de session est gardé en mémoire côté API, lié au compte Plex et à son autorisation, jusqu’à la première expiration Ouicheur/Plex. Déconnexion du Hub, suppression ou changement d’identité, retrait de connexion, expiration ou redémarrage retirent cet accès local. Retirer la connexion du Concierge ne révoque pas les autres sessions Ouicheur.

Le contrat a été lu dans la révision exacte installée : `POST /api/login`, cookie `wishlister_session`, `GET /api/account/sessions`, rendu `/?preview=1`, `GET /api/wishes` avec `mode=public` et le `list` sélectionné. La vue preview désactive l’élévation propriétaire et conserve l’identité du destinataire. La liste des choix vient des options HTML du sélecteur visible, sans interpréter les scripts React ni les données d’administration. Une évolution de cette interface demande une nouvelle vérification de contrat. Les liens sont construits vers `/lists/{id}` depuis les identifiants lus.

Chaque lecture vérifie la session Ouicheur avant et après : une session expirée ne doit jamais retomber sur une vue anonyme, dont les protections de surprises diffèrent. L’autorisation est aussi revérifiée dans le Concierge avant restitution. Les descriptions d’envies peuvent être lues par leur destinataire, y compris lorsque `surprise_hidden` masque leurs réservations. Aucun champ de réservation, achat, financement, contribution, donateur, lien de partage ou suggestion secrète ne sort du connecteur. L’outil ne dit jamais qu’un cadeau est libre. Les budgets totaux déclarés sont indiqués en divisant les centimes par 100, sans les présenter comme des prix marchands actuels. Les offres marchandes ne sont pas consultées.

Validation synthétique : compte personnel, autre compte sans association, privé/public, cookie expiré pendant une lecture, suppression de connexion pendant le login, refus des redirections avec identifiants, projection sans réservations/donateurs, contrats OpenAPI et formulaire Hub sur mobile/ordinateur. Pas de connexion réelle avec le mot de passe d’un membre pendant cette passe ; la première recette réelle se fait depuis son propre formulaire Hub.
